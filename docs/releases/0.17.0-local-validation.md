# Lope 0.17.0 pre-publication validation record

Snapshot date: 22 October 2026, before release integration and publication.
The results below describe the local candidate at that point, not the current
publication status. The operator subsequently approved integration and release;
exact-commit CI and package publication remain independently verifiable through
[GitHub Actions](https://github.com/traylinx/lope/actions) and the
[release tag](https://github.com/traylinx/lope/releases/tag/v0.17.0).
No global provider permissions changed. This is a bounded runner/review/release-
path audit, not a claim that every Lope subsystem was exhaustively audited.

## Diagnosis and changes

1. Agy's native stderr reported a command tool auto-denied because headless mode
   could not ask permission. Lope previously labelled the empty output a parse
   failure. It now emits terminal `tool_permission_denied`, preserves the trust
   boundary, does not accept preparatory stdout, retry, grant or bypass permission.
2. Optional review-only command/stdin/working-directory profiles reduce unrelated
   startup context. Explicit profiles cannot silently drop their prompt. Isolated
   cwd also sets child `LOPE_WORKDIR`, but retains HOME/global provider policy and
   is **not** a tool, network or filesystem sandbox. Ask/implementation stay on the
   original command and cwd.
3. Consensus JSON now retains actual usage, events and circuits. Authentication,
   empty output and permission failures have distinct runtime outcomes. Quoted
   source/model diagnostics cannot forge the permission classification.
4. Preserve the installed Claude safe-mode/session-persistence fix in source.
   Native flag parsing was checked, not a full native Claude review.
5. Cancellation signals precede process-table telemetry. Identity/census probes
   are bounded; an absent process group avoids `ps`. TERM/KILL/census share a
   0.7s deadline; cancellation output drain gets 0.1s inside the parent's existing
   1s reserve. Failed/unknown cleanup is not successful output. Process-target
   counts are leader lower bounds, not exact descendant counts.
6. Temporary review-directory cleanup failures warn without replacing the model
   result or original exception. Release instructions no longer recommend a hard
   reset over a dirty installed checkout.
7. All six version surfaces prepared as 0.17.0. Prior unreleased October harness
   work remains included; unrelated local skill/config work remains untouched.

## Native review evidence and limits

- Agy minimal native text-review smoke: 8.54s, completed, no tool steps observed.
- Broad Lope patch review: Agy timed out at its configured 360s; Grok completed
  in 437.64s. Partial quorum, not a two-model approval.
- Focused Agy cleanup review: completed in 339.25s with a temporary 900s provider
  budget / 1000s whole-run budget. Feedback corrected cumulative cleanup waits,
  repeated telemetry and unknown-count handling.
- Grok feedback hardened diagnostics, profile validation and cleanup handling.
  Its speculative writer-failover concern was checked against actual code and
  disproved by a regression test. No provider approved every final byte.
- The broad review's 1200s total envelope was smaller than Grok's configured
  1800s ceiling. Grok finished well before it, but this is not a recommended full-
  budget invocation. Preserve both provider and whole-run budget headroom.
- These are macOS native/provider and keyless test results, not Linux CI or
  Windows qualification. The Agy profile reduces startup interference; it does
  not guarantee tools will never be requested or that every large review fits
  its unchanged default 360s timeout.

## Publication gates

At this snapshot the source branch was `fix/codex-model-pin`, not main. Remote
main was `84852213a50eea15df737d7b005631c198c99692`, containing the Codex model fix
and later skill documentation. Subsequent integration uses a separate clean main
worktree so the operator's dirty checkout and installed modifications are preserved.
The following are release gates, not assertions that publication already happened.

Before publication:
1. Review the exact candidate diff, including earlier unreleased harness work.
2. Obtain explicit approval for integration, commit, push/tag and publication.
3. Reconcile current main without discarding source or installed modifications.
4. Verify exact-commit Linux Python 3.9/3.12 CI, packaging, version sync and scans.
5. Approve/update final release notes, then publish the tag. Package publishing
   now requires explicit opt-in variables; this release is GitHub-only.
6. Verify GitHub assets/tag parity and perform an approved isolated installer
   check before changing installed host skill surfaces.

See [release procedure](../RELEASING.md) and
[runner contract](../review-harness-repair.md).

## Integrated release qualification (22 October 2026)

The following checks supersede the pre-integration counts above, not the native
review limits. Integration was performed against main in an isolated worktree.

- A Python 3.9 integration run exposed an additional startup/registry-I/O race:
  forced supervisor shutdown could orphan its separate provider process group.
  The POSIX TERM handler now signals that group immediately, even when startup
  has not reached the cancellation loop. A deterministic blocked-registry
  regression verifies provider and descendant death.
- Timeout accounting now preserves subprocess cleanup evidence. No completion
  record means `unknown`, never an inferred `clean`; retries clear inherited
  evidence. Regression coverage includes generation and validation calls.
- Final sequential macOS suites: Python 3.9 **948 passed** (146.31s); Python 3.12
  **948 passed** (155.38s), with 70 existing deprecation warnings. The focused
  regression set passed 65 tests. Deadline/blocked-startup tests passed five
  repeated pairs.
- An isolated installer qualified all eight host layouts, without replacing user
  skills. Isolated status succeeded. A keyless one-round CLI negotiation reached
  normal evidence-gate escalation without a traceback; this is mechanics evidence,
  not a native ensemble approval or accepted implementation plan.
- Fresh interactive paste-install sessions in two real host CLIs were not run.
  Windows native process-tree behavior was not qualified.
- Publication scope is **GitHub only**, explicitly requested by the operator.
  Both package-publishing repository variables are false. No PyPI/TestPyPI
  publisher setup or package-index upload is authorized by this release.

Exact-commit Linux CI and GitHub asset links belong to the hosted release. Local
qualification alone is not proof that those publication gates have completed.
